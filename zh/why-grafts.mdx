AI Agent 可以连接系统，也可以遵循指令。
缺失的一层，是对某个具体功能如何被真正构建的可移植记录，包括它能够安全重做所依赖的决策。

## 三种不同的工作

| 层 | 核心问题 | 典型单位 |
| --- | --- | --- |
| MCP | Agent 能访问或调用什么？ | Server、Tool、Resource |
| Agent Skills | Agent 应该如何完成一类工作？ | `SKILL.md` 目录 |
| AgentGrafts | 这个功能是什么、为何这样做、如何在这里重建？ | `GRAFT.md` 目录 |

<Note>三者是互补关系。Agent 可以用 MCP 检查仓库，用 Skill 指导提取，再用 Graft 把已验证的功能合同带入新项目。</Note>

## 为什么源码还不够

复制模块带走了语法，却经常丢失周围的重要决策：

- 哪些状态对用户可见？
- 哪些失败可以安全重试？
- 哪些操作必须限流或审计？
- 哪些接口稳定，哪些细节可以替换？
- 如何判断移植已经完成？

Graft 让这些决策变得明确、可审查、可验证。

## 这个分类为什么有价值

  <Card title="功能优先" icon="target">功能是一等资产，可以被发现、版本化、审查和复用。</Card>
  <Card title="知识优先于代码" icon="lightbulb">保留意图与约束，不把源项目的实现强行带入目标项目。</Card>

## 实际收益

当项目 B 需要项目 A 已经验证过的能力时，你传递的是一个小而持久的合同，而不是重新开始一次仓库理解。
目标 Agent 仍然会为项目 B 编写原生代码。
真正有价值的经验不会因为项目边界而丢失。
