一个 AgentGraft 是一个自包含目录，必须包含一个 `GRAFT.md` 文件。
格式可读、可版本控制，并且不绑定具体 Agent、框架或厂商。

## 目录结构

```text
feature-name/
├── GRAFT.md          # 必需：元数据与可移植知识
├── references/       # 可选：源实现摘录与设计笔记
├── assets/           # 可选：图示、Schema 与模板
├── adapters/         # 可选：常见技术栈适配提示
└── tests/            # 可选：行为检查与测试意图
```

## Frontmatter

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `name` | 是 | 由小写字母、数字和连字符组成的标识，最长 64 个字符。 |
| `description` | 是 | 说明功能是什么，以及何时应该使用它。该字段用于发现。 |
| `version` | 建议 | 合同发生变化时使用语义化版本。 |
| `license` | 建议 | 明确复用条款。 |
| `tags` | 可选 | 添加 `auth`、`payments`、`webhooks` 等发现词。 |
| `source` | 可选 | 标记来源项目，但不要暴露私有路径。 |
| `compatibility` | 可选 | 记录已知技术栈或架构前提。 |
| `metadata` | 可选 | 存放作者、组织或时间等扩展信息。 |

## 推荐正文

<Tabs>
  <Tab title="意图与行为">解释用户问题、可见结果、主流程和失败路径。</Tab>
  <Tab title="约束与接口">记录安全规则、限制、状态转换、API、事件和核心数据结构。</Tab>
  <Tab title="适配与验收">区分必须保持不变的内容与可以替换的内容，然后定义完成验证方式。</Tab>
</Tabs>

推荐使用以下语义章节：

1. **Intent**：问题与用户可见结果。
2. **Behavior**：成功、失败与状态转换。
3. **Constraints**：适配时不能削弱的规则。
4. **Interfaces**：API、事件、Schema 或伪代码合同。
5. **Dependencies**：服务、库与配置前提。
6. **Adaptation Guidance**：保留什么，替换什么。
7. **Out of Scope**：防止范围无意扩大的边界。
8. **Acceptance**：可观察检查或测试意图。

## 设计原则

- **渐进披露**：先索引元数据，仅在相关时加载完整指令。
- **可移植且可版本化**：合同不依赖源项目私有结构。
- **人类可审查**：文件本身就是可以检查和改进的合同。
- **可组合**：可以单独使用，也可以和 Skills、MCP 配合。
- **知识优先于代码**：references 可以放摘录，但核心必须解释决策。
