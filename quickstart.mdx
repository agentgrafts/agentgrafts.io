The fastest way to understand AgentGrafts is to package one feature your team has already shipped.

## Before you start

- A source project with a feature that works in production or in a verified test environment.
- The files, configuration, and tests that define the feature's behavior.
- A destination project or a second stack where you want to rebuild it.

## Create a Graft

<Steps>
  <Step title="Choose one feature">Pick a bounded capability such as email OTP, webhook signature verification, or a rate-limited API. Avoid starting with an entire subsystem.</Step>
  <Step title="Create the directory">Use a short, lowercase identifier: `email-otp/GRAFT.md`.</Step>
  <Step title="Write the contract">Add frontmatter, then describe intent, behavior, constraints, interfaces, dependencies, adaptation guidance, out of scope, and acceptance.</Step>
  <Step title="Apply it in a new project">Give the agent a direct instruction that names the file and protects the contract.</Step>
</Steps>

```text
Implement this feature from email-otp/GRAFT.md.
Adapt it to the current stack and conventions.
Preserve Constraints and Out of Scope.
Check every item in Acceptance before finishing.
```

## Minimal `GRAFT.md`

```md
---
name: email-otp
description: Email one-time password verification flow. Use when porting email-based account verification.
version: "1.0.0"
license: MIT
tags: [auth, otp, email]
---

## Intent
Verify that a person controls an email address before continuing.

## Behavior
Issue a short-lived code, deliver it, then accept one valid attempt.

## Constraints
- Codes expire after 10 minutes.
- Verification attempts are rate limited.
- Never log the code or return it from an API.

## Acceptance
- Expired codes fail.
- A valid code succeeds once.
- Replays and excessive attempts fail safely.
```

<Tip>The contract is the product. Keep project-specific names and paths in `references/`, not in the portable core.</Tip>
